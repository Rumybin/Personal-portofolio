# Anti AI Slop Standard

## Purpose
This document defines how to keep project output from feeling generic, inflated, or machine-generated.

## Primary Rule
The goal is not to make code messy. The goal is to make it credible, intentional, and human-reviewed.

## What to Avoid
- Generic startup copy.
- Template-like layout repetition without purpose.
- Over-engineered folder structures.
- Decorative effects that do not support content.
- Overexplaining comments.
- Fake personality in code or copy.
- Unnecessary abstractions.
- Perfect-but-empty UI.
- Writing code that looks like it was generated without review.

## What to Prefer
- Specific copy.
- Real project context.
- Clean hierarchy.
- Intentional whitespace.
- Clear trade-offs.
- Simple implementation.
- Human-like judgment.
- Design that matches the creator, not a trend.

## Review Checklist
- Does the result feel specific to TOR Drive?
- Is the structure serving content?
- Is the design restrained and readable?
- Is there any generic filler copy?
- Are there needless layers or wrappers?
- Does the output feel like a real portfolio, not a template?

## Prompt Discipline
- Give specific file-level instructions.
- Limit scope per request.
- Ask for clarification when needed.
- Do not let the model invent missing context.
- Prefer small, verifiable outputs.
